# 🚀 更新日志 | Changelog

## 4.6

* **[严重修复]** charge_guardd 1.7：**充满即停新增「本次插电锁存」**——100% 停充后电池自然放电回到 99% 时**不再自动补电**。锁存按"有没有物理拔电"判定（读取 `power_supply` 的 `online`/`present`，不看会因主动停充而变成 Not charging/Discharging 的电池 status），只有真拔电才解锁，下次插电照常充满。彻底消除睡觉没拔电却 100%→99%→100% 反复浮充的整夜充电循环。沙盒仿真验证：满电停充 → 掉到 99% 保持停充 → 拔电解锁 → 重插充电 → 再满再停
* **[充电]** 新增配置项 `charge_full_latch`（默认 1，WebUI 充电页同步开关）；设为 0 可回到 v1.6 的"掉到 99% 立即补电"旧行为。守护重启 / 总开关关闭 / `restore` 均会清理锁存；另有电量跌到 `power_start` 以下的安全阀，避免极端场景永久不充电
* **[调度]** CPU 采样与调度线程改为**亮/息屏自适应节拍**：亮屏 100ms（保跟手），息屏 500ms（eBPF map 读取、top-app 扫描、消息投递全部降到 1/5），息屏时守护自身唤醒与额外功耗显著下降
* **[调度]** 新增 **前台起步（fg onset）免确认通道**：前台线程刚超闸门且频率还贴地板时，当拍直接到增益曲线算出的目标档，解决轻应用"第一次滑动/点按慢半拍"，同时不改变后台与息屏行为（不增加空转）
* **[调度]** 息屏红线整体收紧：上限 0.35（中核≈1.3GHz / 超大核≈1.5GHz）、前台空闲封顶 0.30、降频立即沉底，夜间待机更接近官方无感水平
* **[调参]** 三种模式重新定值：省电（增益 0.42、超大核单独封 0.60）、标准（增益 0.50、超大核 0.85）、性能（撤掉 0.10 静态底频、增益 0.62、保留快升）。同时把 `interact_fg_util` 收到 0.18、`spike_jump_threshold` 收到 0.42/0.32，减少信息流抖动误触发高频
* **[安装]** `aegis_adapt.sh` 一键适配同步生成新定值（含按本机簇数动态生成的 `cluster_ceil`，超大核槽位自动识别），避免刷入即适配把新参数覆盖回旧值
* **[版本]** 对外版本号统一为 4.6，唯一真值 `module/module.prop`：`xtask` 产物名、CI Pre-release/Release 版本、`update.json`、README、调参手册全部从它读取；`Cargo.toml` 内部写 `4.6.0`（仅满足 semver 语法，不出现在文件名/发布名里），Releases 从 4.6 起连续编号

## 4.3

* **[严重修复]** charge_guardd 1.6：**充满即停不再受"恢复充电电量"约束**——开启充满即停后，100% 停充只要掉到 99% 就立即补电回 100%（浮充），不再等待电量跌到恢复阈值（如 70%）才恢复；此前 99% 插电会出现一直停充不进电的情况。沙盒仿真验证：100% 停充 → 99% 即恢复 → 补回 100% 再停
* **[严重修复]** charge_guardd 1.6：**预约充电保底电量补电改为 +10% 滞回锁存**——无论距预约时刻多久，电量低于保底（如 20%）就一路补电到 保底+10%（30%）才停，不再"20% 停 19% 又充"反复抖动；补电优先于预约按住，电量在保底之上时才执行预约按住/放行逻辑。沙盒仿真验证：25% 按住 → 掉到 19% 触发补电 → 一路充到 30% 才恢复按住，全程无中间停充
* **[构建]** CI 新增 charge_guardd 源码编译步骤（NDK bionic 静态链接），发布包内二进制与 `charge_guard.c` 严格一致
* **[WebUI]** 充电页文案同步：充满即停说明（忽略停止/恢复电量，99% 即补电）、保底电量说明（低于自动补至 +10%）、sched_state=3 状态显示"补电至保底+10%"

## 📦 v2.0.2（上游基础版本历史记录）

### 🎯 新增 (New Features)
* **[CLG]** 新增 8 个可调参数，全面开放调频行为定制：
  - `headroom_ramp`：headroom 在 up_threshold 附近的过渡带宽度（默认 0.15）
  - `up_jump_threshold`：快速升频通道的跳变幅度阈值（默认 0.35）
  - `slow_up_scale`：滞回带内升频的最低速率基准（默认 0.02）
  - `slow_down_scale`：滞回带内降频的缩放系数（默认 0.5）
  - `down_fast_threshold` / `down_fast_mult`：极低负载快速降频的触发阈值与放大倍数
  - `spike_jump_threshold` / `spike_decay`：单 tick 尖峰抑制的跳变阈值与衰减比例

### ⚡️ 优化与特性 (Optimizations & Features)
* **[CLG]** CPU 负载调速器全面重构：
  - **降频不再锁死高位**：滞回带内（down_threshold ~ up_threshold）目标低于当前即可降频，按慢速/正常/快速三档平滑回落
  - **headroom 平滑过渡**：在 up_threshold 附近线性渐变，消除负载临界时的频率振荡
  - **中等负载升频提速**：滞回带内升频速率随 util 接近 up_threshold 线性提升，负载回升时不再以 0.008/tick 缓慢爬升
  - **尖峰抑制**：单 tick 负载跳升超过阈值时衰减其增量，孤立瞬时尖峰（如单核 0↔100%）不再瞬间拉满性能；持续负载下一 tick 即全量生效
  - **降频加速**：极低负载（< down_fast_threshold）跳过降频确认期立即快速回落，消除尖峰消失后频率悬停高位
  - **热重载优先**：模式切换/息屏亮屏仅热重载配置，不再全量重建 sysfs writer
* **[AppDetect]** 同模式 ModeChange 去重：配置重载/亮屏恢复不再产生 `balance -> balance` 冗余事件

### 🐛 修复 (Bug Fixes)
* **[CLG]** 修复配置段不生效：`Mode` 的 `PascalCase` 反序列化与 YAML `cpu_load_governor` 键不匹配，用户配置（含 `enabled`）此前从未生效，现全部正确应用
* **[CLG]** 修复 `perf_floor > perf_ceil` 或 NaN/±Inf 配置导致的 `f32::clamp` panic（配置自动规范化并回退默认值）
* **[CLG]** 修复 `release()` 后不恢复 governor/频率：新增接管前状态快照，退出时按序恢复；读取失败不写退化值、恢复失败自动保留重试
* **[Scheduler]** 修复 IPC 线程 panic 后静默死亡：事件循环包 `catch_unwind`，panic 可见并自动释放 CPU 控制权；config watcher 失败增加退避，消除忙循环
* **[Scheduler]** 修复未知/空模式名意外启用 CLG（现默认禁用，不再用默认参数接管 CPU）
* **[i18n]** 修复非法 language 标签导致启动早期 panic（自动回退 en）
* **[FAS]** 修复配置级 clamp panic：perf floor 超过低 ceil、fast_decay 步长边界反转等场景全部规范化
* **[FAS]** 修复 floor-rescue 自救失效：死锁救援不再被 max_inc 截断，可真正跳出 perf_floor
* **[FAS]** 修复 PID 系数被非法 target_fps（0/负/NaN）污染；per-app 帧率档位过滤非法值
